## Proved

**The same checks on both stacks:**

| Check | Dioxus 0.7.10 | Leptos 0.8.22 + Tauri 2.12.4 |
|---|---|---|
| Web build renders (headless Chrome, CI) | yes | yes |
| Windows build runs (CI) | yes; first render 3,444 ms | yes; first render 3,846 ms |
| Update 0.0.1 → 0.0.2, then relaunch | Windows CI, macOS CI and Dan's Mac (306 → 268 ms); Velopack, unsigned | Dan's Mac (352 → 313 ms) and Windows CI (3,846 → 732 ms); signed, with downgrade protection |
| Tab order, shortcuts, sheet keys, form errors | all pass (checked through the macOS accessibility interface) | all pass, same script |
| What VoiceOver reads (the accessibility tree) | passes after two fixes: the page title and list semantics | passes |
| Pan and zoom, by eye | Dan: smooth, but blurry until zoom resized the drawing instead of scaling it; then sharp and smooth | same technique; not judged separately |

The downgrade protection was also tested by accident. An earlier Windows run offered the 0.0.1 installer labelled as 0.0.2, and Tauri refused it: "The update was signed for version 0.0.1 but the update endpoint announced version 0.0.2" (S-12).

**The first performance scenarios** (pan, zoom, pages, overview, lists, reload at fixed sizes) mostly measured WebKit, which both stacks share. Dan called that out, and the capacity test replaced them. Their runner numbers are in the `trials.yml` runs.

**Ecosystem, as found:**
- **Dioxus:**
  - 0.7 pins wry 0.53, last patched 2025-10-22; current is 0.57. Dioxus 0.7 and current Tauri can't even share a lockfile, because they pin different `webkit2gtk` versions.
  - dioxus-web 0.7.10 doesn't compile with `document` but without dev tools: a missing web-sys feature, worked around in the trial.
  - Its macOS layer pulls `block` 0.1.6, which warns it will break in a future Rust.
  - Its release builds include a dev-server client.
- **Velopack:**
  - its feed is unsigned
  - `zip` 8 carries 3 RustSec advisories and 5 GitHub advisories, one critical
  - at startup it applies any newer package left in its cache, without checking a feed (seen on Dan's Mac)
- **Leptos:** even a browser-only app compiles `server_fn` and the wasm-split macros, which bring CC0-1.0 and BSL-1.0 (D-044).
- **Tauri:** nothing failed in the stack. The failures were the trial's own: a security policy blocking the app's wasm, and a feed server not listening on `127.0.0.1`.
