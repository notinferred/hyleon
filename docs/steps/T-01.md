Completed 2026-10-29. Commit `3c8cd07`. Passing run: [40849948869](https://github.com/notinferred/hyleon/actions/runs/40849948869).

## Built

- **The workspace:** Rust edition 2024, resolver 3, `publish = false`, `unsafe_code = "forbid"` for every crate, exact pins, and `Cargo.lock` committed.
- **Empty crates from the [code map](../ARCHITECTURE.md),** each named `hyleon-…`, with no internal dependencies yet:
  - `crates/core/`: units, model, catalog, calc, packs, checks, layout, render, sheets, export, app
  - `crates/adapters/`: store, mcp
  - `crates/binaries/`: cli (the `hyleon` binary), ui
  - sim, dwg and api aren't created, since the code map marks them for later
- **`crates/guardrails`:**
  - the layer table and the home of each outside system, as data
  - the layering and ledger checks, run on the real workspace and on `DECISIONS.md`
  - two fixture tests, so a broken checker can't pass everything
- **No I/O in the core:** `crates/core/clippy.toml` disallows the file, network, process and clock APIs in every core crate.
- **`deny.toml`:**
  - D-016's licences
  - advisories, at the defaults
  - wildcards denied
  - 15 language-model SDK crates banned
  - unknown registries and git sources denied
- **CI** (`.github/workflows/ci.yml`): one Linux job that runs:
  - format, clippy with warnings denied, cargo-deny, nextest and doc tests
  - the wasm32 build of every crate under `crates/core/`

## Proved

**On `main`.** Every check passed on a clean checkout:
- format, clippy and cargo-deny
- the 5 tests and the doc tests
- the wasm32 build of all 11 core crates

**On a temporary branch.** The branch, `t01-negative-checks`, has been deleted. Its commit made five deliberate changes, and CI caught each one:

| Change | Caught by | Run |
|---|---|---|
| `hyleon-model` depends on `hyleon-store` | the layering test: "hyleon-model (layer 1) depends on hyleon-store (layer 9)" | both |
| `std::fs::read` in `hyleon-calc` | clippy: "use of a disallowed method `std::fs::read`" | both |
| a 617-character row in DECISIONS.md | the ledger test: `("D-999", 617)` | [40850101741](https://github.com/notinferred/hyleon/actions/runs/40850101741) |
| `rio` (GPL-3.0) in `hyleon-units` | cargo-deny: "license is not explicitly allowed" | [40850321477](https://github.com/notinferred/hyleon/actions/runs/40850321477) |
| `clust` (a language-model SDK) in `hyleon-units` | cargo-deny: "crate 'clust = 0.9.0' is explicitly banned" | 40850321477 |

**Why it took two runs:**
- **First run.** The two test crates were behind `cfg(any())`, a condition that's never true. cargo-deny rightly treats such dependencies as part of no build, so it skipped them.
- **Second run.** As Windows-only dependencies, which CI never compiles, they were caught.
- **Extra findings.** cargo-deny also flagged advisories inside those two test crates' own trees: a use-after-free in rio, an integer overflow in an old `bytes`, and two unmaintained crates.
- **Ledger test.** nextest stopped at the first failing test in the second run. CI now uses `--no-fail-fast`, so one run reports every failure.

## Decided within the approved plan

- Core I/O is caught by clippy, not by the layering test. STEPS asked for "the build or the layering test", and CI's clippy step is part of the build.
- Only the formatter (`rustfmt`, which compiles nothing) ran on the Mac, besides resolving `Cargo.lock`. The plan named only the lockfile; formatting by hand would likely have failed CI.
