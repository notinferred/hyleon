## Scope as selected

Dan chose every recommendation from the [CI and delivery research](../research/2026-10-29-delivery.md), and Blacksmith for runners:
- **The tiered architecture** (D-037). Each tier starts at its phase or at a measured CI time.
- **The commit flow** (D-038). Work goes to `staging`; CI fast-forwards `main` when its checks pass.
- **Runners and spending** (D-039). Blacksmith runs the Linux checks. GitHub has no payment method, so its usage stops at the $12 a month included.
- **Small changes now:**
  - time limits on jobs and tests
  - a daily advisory check
  - docs-only pushes skip the Rust checks
  - Dependabot alerts only
- **A security-fix exception** to the two-week pin rule, in [CLAUDE.md](../../CLAUDE.md).

Dan will set up code signing himself; the accounts will also serve his other app. Signing arrives with the release tier in phase 1.

## Built

- **`.github/workflows/ci.yml`:**
  - `changes` runs on GitHub's `ubuntu-slim`. It skips the Rust checks when every file changed since `main` is documentation no check reads.
  - `check` runs on `blacksmith-2vcpu-ubuntu-2404` with a 10-minute limit.
  - `promote` runs on `ubuntu-slim`. It fast-forwards `main` through the API, so the write token never reaches a vendor's machine.
- **`.github/workflows/scheduled.yml`:** a daily `cargo deny check advisories` at 06:17 UTC on Blacksmith, with a 5-minute limit.
- **`.config/nextest.toml`:** a test still running after 2 minutes is stopped.
- **Dependabot:** alerts were already on and its update pull requests already off, so nothing changed.
