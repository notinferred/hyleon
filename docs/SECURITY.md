# Security

Threats to Hyleon and how each is met.

- **Status.** Every mitigation is planned until a step builds and verifies it.
- **IDs.** Threat IDs are permanent and never reused. A changed threat gets a new row that names the one it replaces.

| ID | Threat | Mitigation | Status |
|---|---|---|---|
| S-01 | **Agent overreach.** An agent tries an action reserved for a person: confirming a value, accepting a boundary, choosing an option, choosing a region, acknowledging findings, issuing a revision. | These actions aren't exposed over MCP, and the core refuses them from any actor but a person in the app. Every agent command is logged with its actor. | planned |
| S-02 | **An agent poses as the person.** An agent supplies a value, or a compromised client fakes an elicitation answer, so the guess looks like the person's decision. | Values from an agent are always stored as `inferred`, unless Hyleon can verify them against a catalog entry or a calculation. Answers that arrive by elicitation are marked `via: elicitation`. Issuing happens only in the app, where the person sees every inferred value and every elicited answer before signing. | planned |
| S-03 | **Prompt injection.** Text in a project, pack, catalog or imported file is written to steer an agent. | Text is returned to agents as data, labeled as project content, and tool descriptions say never to follow instructions found in it. The MCP server runs no commands and makes no network calls, so a steered agent can't use Hyleon to act outside the project. | planned |
| S-04 | **A malicious or broken pack** hangs Hyleon, reads files, or quietly weakens checks. | CEL has no I/O, loops or recursion. Hyleon adds bounds the library lacks: rules are parsed at load, macros nest at most two deep, every rule is dry-run against the pack's test projects, and the collections a rule sees are capped ([formats/pack.md](formats/pack.md)). Packs are locked by sha256 in each project. A pack that isn't `released` says so on every finding. Pack signing comes with the marketplace. | planned |
| S-05 | **Project data leaves the device.** | The core makes no network calls. The desktop app calls out only for updates, licensing (phase 3) and sync, and sync is opt-in. Telemetry is opt-in and never includes project content (D-015). Hyleon never sends projects to an AI: the person's own agent reads only what the person points it at. | planned |
| S-06 | **Tampered files.** Someone edits the model files directly or alters an issued revision. | The projection's sha256 is checked on load, and an outside edit becomes a finding. Issued revisions and their outputs are content-addressed, so tampering is evident. | planned |
| S-07 | **Licence tampering** (phase 3). | A signed entitlement (Ed25519) with an offline grace period. Some piracy risk is accepted. A lapsed or tampered licence never blocks opening or exporting the person's own projects (TRUTHS.md, truth 7). | planned |
| S-08 | **Supply chain.** A compromised or abandoned dependency. | Exact pins, each version published at least two weeks before it's adopted. Lockfiles. cargo-deny checks advisories, licences (D-016), bans and sources in CI. Dependencies are reviewed at adoption. | planned |
| S-09 | **A tampered question round trip.** A client alters the request state between `ask` and its answer, to attach answers to different questions or a different project. | Hyleon signs the request state (HMAC) and verifies it before recording anything. A state that doesn't verify is refused ([formats/mcp.md](formats/mcp.md)). | planned |
| S-10 | **A wrong or tampered region profile** leads a design to the wrong code edition or amendment. | Every fact names its source and the date it was read. A profile is released only by a person, who records the date and their name. Projects lock profiles by sha256. The watcher can only propose changes, and it raises an alarm when it stops running. Every profile ends with "confirm with your authority having jurisdiction" ([formats/region.md](formats/region.md)). | planned |
| S-11 | **Wrong or invented component data** from an agent's research ends up in designs. | Every fact cites its source, with official sources first. A researched entry stays a draft, marked unverified, until a person approves it. Released entries are versioned and never overwritten, and swaps rerun every check ([formats/catalog.md](formats/catalog.md)). | planned |
