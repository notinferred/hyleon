# Research record: market, constraints and stack (2026-10-28)

This record is never edited. A later round of research gets a new file, which names anything here it corrects.

## How this was done

- **Method.** Five research agents worked in parallel, each with a narrow brief, all on 2026-10-28:
  1. competitors and pricing
  2. segments and size
  3. how people use AI for technical drawings
  4. legal, professional and format constraints
  5. the stack check
- **Sources.** Primary sources were preferred: vendor pages, statutes, standards bodies, agency data and official docs.
- **Markers:**
  - **\*** marks a vendor's claim about itself.
  - **(A)** marks an assumption.
  - "Unknown" means it wasn't found; nothing was guessed.
- **Limits.**
  - Several agents ran out of web searches partway through and went on with direct fetches.
  - Some sites blocked automated reading: Reddit, autodesk.com, and some forums.
  - The constraints section is research, not legal advice.

## The starting evidence: one real site's document set (anonymized)

Hyleon began with one site's control-system documents, built partly with AI and partly in CAD. The client and every identifier are left out. The set showed:

- **Six tools with no shared data:** 2D CAD, 3D CAD, a PDF markup tool, a vector drawing tool, script-rendered SVG, and a word processor.
- **Mixed paper standards:** ISO A3 and A1 sheets alongside ANSI B and US Letter.
- **Nine mismatches between documents:**
  1. one pump with two different tags on different sheets
  2. the same tag written two ways ("-1" and "-01")
  3. one flowmeter numbered differently on two diagrams
  4. one abbreviation meaning two different things in two documents
  5. one tank under two names, with the same drawing number
  6. two temperature transmitters placed in the tank on one document and on pipes on another
  7. one gateway on the network drawing, three on the system drawings
  8. one destination named three ways
  9. a mistyped drawing reference, plus references to drawings missing from the set
- **Limits buried in prose notes,** for example "BSP threads only, no NPT", "+24 V on this row is for the safety function only", "1 A per output".
- **Open items written inline as "TBD" or "to confirm",** with no list that tracked them.

## Summary: what this means for Hyleon

- **No product combines Hyleon's four core ideas:**
  - checks that work with any AI agent
  - one model across disciplines for small teams
  - a source on every value
  - questions before design
- **The closest concept is WSCAD ELECTRIX OS,** which comes in 2027. It is electrical only, uses WSCAD's own agents, and has no MCP. The closest AI-native product is Outerport (YC S24): checked electrical and P&ID design models, sold to enterprises. Nothing targets UL 508A panel shops or small integrators.
- **The first market:** integrators (about 3,000 in North America) and UL 508A panel shops (about 4,058 in the US). Both are small, countable and reachable, and they spend more on software per employee than electrical contractors. Contractors (79,611 firms) come second.
- **The "verifier" thesis holds where checks exist.** In every field studied, adding a checker gave the largest measured gain. But some parts of physical design already have checkers: PLC compilers, network verifiers, EDA rule checks, and the checks inside each CAD tool. The open gap is narrower and more defensible:
  - code compliance (sizing; which edition applies)
  - consistency across drawings, tools and disciplines
  - piping and process-diagram meaning
  - questions asked before design
- **Demand is unproven for one part of the pitch.** AI use is broad but shallow, and no professional was found relying on AI-drawn images. User interviews come before building on that part.
- **Code text is the largest legal constraint.** IEC and ULSE terms forbid building software from their documents without permission. NFPA has no public licence for software. Packs must hold clause references and Hyleon's own check logic. Table values must come from the person or from a licence (D-017).
- **Professional rules fit the product.** Licensing boards' AI guidance asks for records that let a licensee reproduce and verify the work, which Hyleon's log provides. Hyleon must never seal, and unsealed sheets carry "PRELIMINARY, NOT FOR CONSTRUCTION".
- **The stack holds, with corrections:**
  - MCP questions use multi round-trip requests
  - CEL needs Hyleon's own bounds
  - Typst attachments are `pdf.attach`
  - Dioxus updates go through Velopack
  - elkjs is EPL-2.0

### The closest competitors

- **WSCAD ELECTRIX OS** (premiered 2026-10-13; on sale in 2027) ([WSCAD](https://www.wscad.com/us/wscad-presents-electrix-os/)):
  - breaks specifications into verifiable requirements, with their origins
  - asks when information is missing or conflicting
  - its own agents propose power, control and safety concepts, which are checked before they enter the model
  - logs every step\*
  - electrical only; targets OEMs, machine builders, integrators and panel builders
  - no price, no MCP
- **Outerport (YC S24)** ([outerport.com](https://outerport.com), [YC](https://www.ycombinator.com/companies/outerport)):
  - an electrical design language "backed by thousands of unit tests"
  - drawing sets, BOMs and calculations; P&ID checks for continuity, tags and instrument coverage; simulated control logic\*
  - enterprise customers (Daikin named)
  - no MCP, network coverage or public price found
- **EPLAN Cogineer** ([docs](https://www.eplan.help/help/cogineercloud/en-us/Content/htm/cogineer_intro.htm)):
  - rule-based generation of variants defined in advance; doesn't ask open questions, carry sourced limits or check designs
  - Copilot adds answers and part lookup, with no outside agents
- **AutoCAD Electrical:** $2,095 a year with AutoCAD. Its assistant is a preview, its local MCP is mostly read-only and only for Autodesk's assistant, and it has no requirements or source layer ([third-party review](https://www.meltflexai.com/blog/autocad-mcp)).
- **Other AI-native startups:**
  - Endra: AI design of building mechanical, electrical and plumbing systems, with firm "Playbooks"; $50M Series A, a16z, 2026-06 ([endra.ai](https://www.endra.ai/))
  - Operon (YC S26): plant documents into a queryable model
  - Structured AI (YC F25): AI review of drawing sets against building codes; $4.2M seed
  - Augmenta: building electrical design; $10M seed, 3/2025
  - Solvera and Marengo: AI-assisted engineering services, not software

### Gaps no product fills

- **Verification that works with any AI agent.** No electrical, controls or piping design tool lets an outside MCP agent propose changes the product checks before a person confirms. Open MCP access exists only in diagram and record tools.
- **One model across disciplines for small teams.** Multi-discipline single-model suites are enterprise products priced by quote. WSCAD is the broadest small-team tool but leaves out networks.
- **A source on every value.** Not on sale. The nearest are ELECTRIX OS requirement origins (2027) and Outerport's source-cited digitized values\*.
- **Questions before design.** Only ELECTRIX OS, electrical only, in 2027.
- **Per-job scenario packs.** No product does this. The nearest are Cogineer configurators and Endra Playbooks.

## 3. How people use AI for technical drawings

### Practice

There's little evidence of AI use for drawings specifically; the use found is mostly questions and answers, code and configuration. No professional was found relying on an image generator for real wiring, panel, P&ID or piping drawings.

Anecdotes and trade press:
- AI is useful for learning the code but has been "WAY off" on fuse coordination ([Mike Holt forum](https://forums.mikeholt.com/goto/post?id=2959303)).
- On ladder logic: "zero success" ([MrPLC](https://mrplc.com/forums/topic/43898-using-chatgpt-to-write-ladder-logic/)).
- Schematics drawn by Claude Code had "Wires … not connected to pins". Asked whether it saved time: "No" ([EEVblog, 3/2026](https://www.eevblog.com/forum/eda/claude-code-for-pcb-design/25/)).
- Counterexample: a board designed with an AI model worked with no manual edits, after about $450 of API use and some wrong component choices ([report, 9/2026](https://letsdatascience.com/news/developer-uses-claude-fable-5-for-pcb-design-b80f814e)).

Teams build their own checkers:
- Wipro and AWS added a rule-based evaluator to an AI ladder-logic generator ([ZenML case](https://www.zenml.io/llmops-database/ai-powered-plc-code-generation-for-industrial-automation)).
- Rockwell's Copilot warns it "may display inaccurate information" and can't change safety code.

### Failures

- **Image generators** connected an LED strip's channel to power and +12 V to ground; on a power-supply schematic, "both generators have a problem" ([Elektroda](https://www.elektroda.com/news/news4172034.html), informal tests).
- **Board-level tasks.** The best model passed 8.15% of 300 tasks graded by rule checks and simulation ([HWE-Bench, 2026](https://arxiv.org/abs/2603.18102)).
- **Code compliance.** AI output was "plausible but incomplete, omitting key National Electrical Code (NEC) requirements" ([ASEE 2026](https://nemo.asee.org/public/conferences/374/papers/50178/view)).
- **Network configurations.** GPT-4 on its own made "egregious errors in topology, syntax, and semantics" ([Mondal et al.](https://arxiv.org/abs/2307.04945)).
- **Repeatability.** The same prompt gives different findings on different runs ([DRCY](https://arxiv.org/abs/2603.15672)).
- **Images as input.** A graph representation of a P&ID was 18% more accurate than images ([ChatP&ID](https://arxiv.org/abs/2603.22528)).

### Adoption surveys

- **Use is broad:** 43% of top electrical design firms and 25% of the top 50 contractors were already using AI, uses unspecified ([EC&M, 2024](https://ecmweb.com/55274926)).
- **Trust is falling:** 65% trust AI in their field, down 11 points ([Autodesk, 2025](https://adsknews.autodesk.com/en/news/2025-state-of-design-and-make/)).
- **Rising at work:** generative-AI use at work in architecture and engineering jobs rose from 29.8% (7/2024) to 60.9% (7/2026) ([FRED](https://fred.stlouisfed.org/data/RPSGENAIUSAGESHAREOCC4)).
- **Not found:** no survey measures AI use for drawings, and NECA, CSIA and ISA publish none.

### Editable outputs and research

- **draw.io** warns that AI tools "may not return sensible results" ([draw.io](https://www.drawio.com/docs/manual/insert/insert-generate/)).
- **Text to P&ID** ([ACPID](https://arxiv.org/abs/2412.12898)): agents write a domain language that rules turn into DEXPI and Visio. It scored 96.96% "soundness", but that measures whether requested items appear, not whether they're right.
- **Text to DEXPI** ([2026](https://arxiv.org/abs/2609.12656)): an intermediate format cut the prompt from about 122k tokens to about 650, but "does not eliminate engineering inconsistencies."
- **Electronics:** Flux runs rule checks continuously. Passing DRC "does not guarantee that a PCB is electrically correct" ([JLCPCB](https://jlcpcb.com/blog/claude-code-pcb-design)).

### How other fields give AI a verifier

- **The principle:** "Software 2.0 easily automates what you can verify" ([Karpathy](https://karpathy.bearblog.dev/verifiability/)). A task gets easier to verify by "front-loading some research about the task" ([Jason Wei](https://www.jasonwei.net/blog/asymmetry-of-verification-and-verifiers-law)), which is what Hyleon's questions do.
- **Measured gains from adding checkers:**
  - PLC: grammar checker, compiler and model checker raised success from 47% to 72% ([LLM4PLC](https://arxiv.org/abs/2401.05443))
  - Verilog: 24.2% more accurate with compiler feedback ([AutoChip](https://arxiv.org/abs/2311.04887))
  - networks: about 6–10× leverage from verifiers ([Mondal et al.](https://arxiv.org/abs/2307.04945))
- **Checks can be gamed:**
  - weak tests inflated SWE-bench results by 6.2 points ([study](https://arxiv.org/abs/2503.15223))
  - models modified the tests in 30.4% of runs ([METR](https://metr.org/blog/2025-06-05-recent-reward-hacking))
  - 44.2% of chip code that passed testbenches failed formal verification ([RealBench](https://arxiv.org/abs/2507.16200))
- **A solver isn't enough on its own.** FEA agents produced runnable calls but "were not able to completely and correctly solve any problem" ([FEABench](https://research.google/pubs/feabench-evaluating-language-models-on-real-world-physics-reasoning-ability/)). A solver checks physics, not whether the model matches the problem.

### Implications

- **For the thesis:** checkers give the largest measured gains everywhere, and schematic generation without them does badly.
- **Against a broad version of it:** checkers already exist for PLC code, networks, electronics and inside each CAD tool. Hyleon's claim is to check what nothing checks today, not to be the first verifier.
- **Checks are only as good as their specification, and agents learn to game them.** That makes question-driven requirements and sourced limits the core of Hyleon, not an add-on.
- **Demand for fixing AI-drawn images is unproven.** Interview users first (ROADMAP, phase 0).
- **The research keeps arriving at the same design:** a structured model that is checked, then written out as drawings. That's Hyleon's design.
- **Image models improve each release,** and incumbents add AI where they already own the checks. Electronics is crowded; panels, controls compliance and P&IDs less so.

## 4. Legal, professional and format constraints

### Code text

- **NFPA (NEC):**
  - free access is read-only and requires an account
  - copying needs permission
  - no public software licence; licences are negotiated case by case, and one integrator pays $462 per user per year for NFPA 1 ([NFPA](https://www.nfpa.org/customer-support/terms-of-use), [ImageTrend](https://www.imagetrend.com/nfpa-codes/))
  - NFPA's lawsuit against UpCodes settled in 2025 with a licence
- **ULSE (UL 508A),** under its July 2026 policy:
  - derivative works are barred, "including … large language models and Generative AI"
  - submitting its content to any AI needs permission ([policy](https://ulse.org/wp-content/uploads/2026/07/ULSE-External-Copyright-Policy-Jul-2026.pdf))
  - a free Digital View exists
- **IEC:** purchased standards may not be used "for the development of any algorithm, digital model, software program, or AI tool" without permission ([terms](https://webstore.iec.ch/en/terms-conditions)).
- **Courts:**
  - Non-commercial sharing of standards incorporated into law is fair use (ASTM v. Public.Resource.Org, D.C. Cir. 2023).
  - A for-profit service's posting is likely fair use (ASTM v. UpCodes, 3d Cir. 2026, preliminary).
  - US appeals courts disagree on whether incorporated standards keep copyright, so it's **unclear**.
  - The Pro Codes Act is pending.
- **What's safe (analysis, unclear in places):**
  - citing clause numbers
  - writing requirements as our own check logic
  - single table values are arguably facts; copying whole tables risks the protected selection and arrangement
  - fair use covers incorporated standards such as the NEC, but less clearly UL 508A or IEC texts
  - purchase terms can forbid what fair use allows

### Professional engineering

- **NCEES Model Law (August 2025).** "Responsible charge" means full professional knowledge of, and control over, the work.
- **NCEES Model Rules:**
  - final drawings to clients or agencies are sealed
  - unsealed working documents say "PRELIMINARY, NOT FOR CONSTRUCTION, RECORDING PURPOSES, OR IMPLEMENTATION"
  - a licensee seals only work under their responsible charge ([NCEES](https://ncees.org/wp-content/uploads/2025/09/Model_Rules_August-2025_web.pdf))
- **AI guidance:**
  - NSPE asks for verification and transparency.
  - North Carolina's board (2025) requires the licensee to be able to reproduce AI output independently, verify the inputs, and keep records of inputs, methods and validation ([NCBELS](https://www.ncbels.org/wp-content/uploads/2025/07/Guidelines-on-the-Use-of-Artificial-Intelligence-in-Engineering-and-Surveying-Services-FINAL.pdf)).
  - Florida's board warns against stamping without "meaningful oversight".
- **Contractors and panel shops:**
  - California lets contractors design what they install.
  - Florida lets electrical contractors design what they install up to $125,000 and 800 A at 240 V, commercial.
  - Texas exempts manufacturers for their own products, but may still require sealed plans.
  - Whether UL 508A shop drawings need a seal is **unclear**: it depends on the jurisdiction.
- **How vendors limit liability:**
  - the user is solely responsible for outputs and for testing them
  - liability is capped (Autodesk: the prior year's fees or US$1,000)
  - German law bars excluding liability for injury or gross negligence

### UL 508A

- **Marking.** NEC 409.110 requires a panel's short-circuit current rating to be marked. UL 508A Supplement SB is the named method: take the lowest component rating, optionally adjusted for current-limiting devices ([Siemens white paper](https://assets.new.siemens.com/siemens/assets/api/uuid:e38c994f-b2da-4846-ba00-f8e4733dfbde/ulsccr-whitepaper-icp-us.pdf)).
- **What a listed shop needs:** a UL-qualified technical representative (MTR) on site, a procedure document UL writes for the shop, and follow-up inspections.
- **Existing tools:** Eaton's OSCAR (subscription) calculates SCCR, and FC2 (free) calculates available fault current.

### File formats and data

- **DWG:**
  - writing it is lawful
  - the trademark status is unclear
  - RealDWG costs $8,000 a year and can't run on a server
  - Open Design Alliance tiers that allow web use exist; fees unverified
- **DXF:** Autodesk publishes the reference for anyone writing programs, with no fee stated.
- **PDF/A:** part 3 adds attachments, each with a declared relationship to the document; part 4f allows attachments; part 4e covers engineering content and replaces the little-used PDF/E.
- **DEXPI:** published under a Creative Commons licence.
- **AutomationML:** its library is MIT-licensed; the specification's licence is unclear.
- **ETIM:** the classification is under ODC-By 1.0 and free; its xChange format is Apache 2.0.
- **BMEcat:** a royalty-free implementation licence from BME is needed.

### Apple

- **SF fonts:** "solely for creating mock-ups of user interfaces" for Apple's own operating systems; no embedding, and no web content ([Apple fonts](https://developer.apple.com/fonts/)).
- **SF Symbols:** only in apps for Apple products, never in icons or logos.
- **The guidelines' text:** may not be republished; paraphrasing ideas and linking to them is likely fine.

**Findings that changed the plan:**
- **MCP elicitation.**
  - MCP 2026-07-28 removed server-initiated requests. Questions now use multi round-trip requests: the tool returns the input it needs and a request state, and the client calls back with the answers.
  - The state is attacker input and must be signed.
  - Claude Code added elicitation in 2.1.76, confirmed by Anthropic's changelog.
  - Forms are flat, with at most 16 inputs for MCP tasks ([MRTR spec](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr), [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)).
- **CEL.**
  - It passes 67% of the conformance tests.
  - It has no execution budget (the pull request was closed unmerged) and no type checker.
  - Hyleon adds parse-time limits, a dry run against test projects, and capped inputs.
- **Typst.**
  - `pdf.embed` became `pdf.attach` in 0.15.
  - PDF/A parts A-1b through A-4 and PDF/UA-1 are supported, with attachments only in A-3 or A-4f.
  - The `World` needs about 100–200 lines of glue.
- **Dioxus.**
  - No desktop auto-updater: Velopack is the option.
  - `dx bundle` builds only for the machine it runs on.
  - The CLI sends telemetry by default.
  - Accessibility is the webview's tree, so the SVG sheets need their own labels.
  - WebKitGTK is the weakest webview.
  - 0.8 alphas break APIs.
- **uom.** Serializing writes only the number, so the unit is lost, and there's no JSON Schema support. Explicit-unit values go at the boundaries.
- **object_store.** The local filesystem rejects update-if-unchanged writes. Hyleon relies only on create-if-absent writes, which both the local filesystem and R2 support.
- **Graph layout.** No Rust crate matches ELK, so elkjs (EPL-2.0) goes in the webview only.
- **WorkOS pricing.** AuthKit is free up to 1M monthly users; SSO and SCIM cost $125 per connection per month at low volume.
